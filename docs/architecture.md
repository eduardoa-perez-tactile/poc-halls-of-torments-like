# Foundation and lobby

The TV/desktop host owns a two-slot LobbyState. Its synchronized methods are short; network sockets and asset I/O do not run in the render loop. The LibGDX UI reads snapshots five times per second and changes labels only when state or reconnect countdown changes.

NanoWSD serves an allowlisted set of local assets over HTTP and accepts WebSockets on the same TCP port, 8787. ZXing generates the join QR from the TV's plain local address. There is one party per TV. The controller page discovers an opaque internal session identifier from GET /session, then automatically connects; players never enter or see a room number. The page has no runtime third-party dependencies.

The WebSocket handshake validates the internal session and browser Origin, claims one of two slots, and returns a player number plus an opaque reconnect token. New phones may join in the lobby or when the host opens Invite Player 2. Existing phones can reclaim reserved slots during any phase. The page sends a heartbeat every two seconds. Ten seconds without a heartbeat disconnects a phone; its slot is then reserved for 45 seconds. The host can remove an occupied or reserved slot. Late callbacks from a previous socket cannot disconnect its replacement. Unknown controller messages cannot invoke remote UI commands.

The browser stores its token under a host/room-specific localStorage key, with a memory fallback if storage is blocked. It explicitly handles full rooms, duplicate tabs, invalid rooms, host removal, backgrounding, and bounded reconnect attempts. A removed phone stops retrying until its user explicitly joins again.

Session identifiers isolate browser reconnect tokens across app restarts. This is an unencrypted home-LAN prototype, not an internet-facing service. Do not expose or port-forward it onto the public internet.

The Android launcher supplies an optional advertised host through the joinHost intent extra. On a physical TV, local IPv4 discovery supplies the address. During emulator development, the Python launcher forwards an ephemeral loopback ADB port and serves a bounded streaming relay on the computer's LAN port 8787. This keeps QR links usable by real phones without depending on the emulator's isolated address.

LibGDX uses a fixed logical 1920x1080 FitViewport with safe margins. The UI is laid out once per screen; geometric D-pad navigation selects enabled controls, and modals preserve/restore focus. Desktop supports keyboard and mouse. Android supports D-pad/OK/Back and uses immersive landscape rendering with touchscreen optional and the TV launcher declared.

Resources are shared across screens. File textures and retained font atlas data support Android GL context restoration; QR textures are regenerated on resume and disposed on replacement. Server threads are stopped and GPU resources disposed at application shutdown.

Home, lobby, dialogs and results share the approved simplified layered crypt and matching stone/brass/ruby theme. Normal and focused plates are separate painted textures baked with identical source bounds; nine-slice views reuse them at different control sizes. There is no post-processing glow or per-frame image processing. At startup, small PNGs for phone panels, button states, wordmark, and backdrop are encoded from the existing baked pixmaps; the server does not retain full-resolution source images for those routes. See docs/layered-menu-art.md for the current environment prompts and docs/home-menu-art.md for unchanged interface art provenance.

AndroidLauncher uses singleTask launch mode so reopening from the TV launcher reuses the existing activity, room, and controller server. A second activity would otherwise fail to bind the same local port and show an offline lobby. The QR area now displays an explicit network/host error instead of a blank artwork panel if hosting or QR generation is unavailable.

ArenaWorld is a rendering-independent, fixed 60 Hz simulation with preallocated pools (64 enemies, 96 bolts, 96 pickups). Frame delta is bounded to 100 ms. It owns movement, dodge, targeting, health, shared pickups, revival, weapons, enemy behaviors, effects, hostile projectiles and final boss outcome. Normal sessions explicitly select the twenty-minute timeline; the no-argument world keeps the short development fixture. A double simulation clock avoids twenty-minute float accumulation drift. Twenty minutes of waves lead to the boss; only its defeat wins. There are no tick-time allocations.

Phones send screen-relative axes and dodge edges at 30 Hz, bound by the server to their own connection. Finite normalized inputs expire after 300 ms, sequence numbers reject replay/out-of-order messages, and pause/background/disconnect clears all input. The render thread polls reusable Controls objects and maps screen axes into world axes. The server publishes own-player health/cooldown feedback at 5 Hz during gameplay without render-thread I/O.

ArenaRenderer projects the shared world isometrically, caches the fixed floor geometry in one managed mesh, depth-sorts a bounded preallocated sprite list, and draws either one camera or two independently scissored vertical viewports. The original painted masters are baked once into a managed 1024x512 actor/prop/FX atlas and 512x512 floor texture (3 MiB total); large source pixmaps are immediately released. No framebuffers or post-processing are used. HUD text is cached at 5 Hz. See gameplay-art.md for provenance.

The TV owns shared screen transitions: Lobby -> Session -> Results; Pause -> Invite -> Pause -> Resume preserves the running world. A fresh second controller joins near its living companion on resume. Reconnection keeps the same generation and existing player health; a replacement controller has a new generation. Any participating controller disconnect pauses simulation, and app backgrounding also pauses. Hero selection and distinct class weapons are implemented; additional arenas and persistent campaign saves remain future work.

Sources: [LibGDX project structure](https://libgdx.com/wiki/start/project-generation), [Android TV setup](https://developer.android.com/training/tv/get-started/create), [NanoHTTPD](https://github.com/NanoHttpd/nanohttpd), [ZXing](https://github.com/zxing/zxing).


GameHud owns only compact combat presentation and reuses the existing atlas pixels and fonts. It draws unboxed text, thin health rails and subtle accents; no background panels or portraits cover the fight. ArenaHudState provides a bounded three-notice queue and a hidden encounter data slot (name, phase, current/max health). CryptLobby raises notices from real start/join/health/alive/time transitions, and freezes notice time along with paused simulation. The simulation populates the encounter slot from the active boss; the profiling-only F4 visual preview remains explicitly labeled. Phone feedback still receives alive/cooldown data for safe input gating, but the simplified page does not display health. Its personal upgrade chooser is the user-authorized exception to remote-owned shared UI.


PartyProgression is owned by ArenaWorld and advances on collected-soul XP. Party level and XP are shared; per-player bounded upgrade entitlements, offers, timers and applied effects remain separate. Choice timers run on simulation time, so manual pause/background/disconnect freeze them without a level-up pause. Each offer lasts 30 seconds, then applies option zero. New levels queue entitlements without restarting a current countdown, and late joining grants catch-up entitlements. Monotonic offer IDs survive run resets to reject stale selections.

The render thread publishes reusable offer data to LobbyState at 5 Hz. WebSocket messages carry only an offer ID and option index; server connection identity selects the slot. LobbyState accepts a matching offer once, queues a generation-tagged request, and the render thread revalidates and applies it through PartyProgression. The phone receives only its own current offer. Twelve traits include damage, attack rate, movement, vitality, evasion, class weapon traits, two secondary attacks, critical hits and pickup attraction; no network I/O runs in the simulation tick.


The complete arena expands bounded pools with 96 hostile shots, 12 ground warnings and 96 effects. Warden attacks a cone directly; Ranger arrows track a per-enemy hit mask for piercing. Secondary attacks reuse the same damage/loot/stat path. Boss ground hazards warn before one impact and respect dodge invulnerability. Hero identity is independent of controller slot; the remote selects an inactive participant's hero before activation. Results read per-player ranks, kills, damage and revives only at the end-screen transition.

GameAudio loads eight short original mono PCM cues once, rate-limits overlapping combat sounds and reads monotonic simulation counters. It stops voices on pause and disposes them on exit. Audio defaults on and a local Sound preference is available through Settings. The visible emulator helper enables host audio; headless checks remain muted. Neither audio generation nor networking runs in the simulation tick.


MenuSceneArt owns one 1536x864 opaque room and one 512x1024 guardian/orb atlas (7.0625 MiB combined). It alpha-crops the two foreground groups independently while preserving their source-canvas positions, then draws the shared orb twice with a subtle eight-second brightness pulse. No fire, fog, post-processing or frame-loop image processing is used. The same scene serves Home, lobby/invite, hero info and both outcomes; phones receive a startup-only 640x360 composite. Managed baked pixels support Android context restoration; full decoded source masters are released. See layered-menu-art.md for provenance and exact bounds.

OutcomeArt.Titles prewarms both 1024x256 wordmarks (2 MiB), and BuildIcons normalizes twelve skill emblems into one 512x384 managed atlas (0.75 MiB). The current screen flow does not create OutcomeArt.Loader or load separate result backgrounds, so results need no additional scene decode/upload. Shared GPU accounting includes MenuSceneArt, gameplay, HUD, fonts, titles, icons and any QR, guarded below 32 MiB. Results skip world rendering. Native summary labels and three real remote controls sit over the shared scene. Run Details adds a scrim and presents unboxed hero illustrations, stat highlights and illustrated rank grids. Back restores focus to Run Details. With no phones connected, replay routes to the lobby instead of silently returning.


RunEquipment owns seven fixed equipped positions per player, cached aggregate modifiers, eight bounded personal loot entitlements and three-card immutable previews. Base skill stats/ranks remain separate; combat, health/Dodge HUD values and phone feedback read effective gear values. Five elite kills plus timeline-relative reliquaries at 7.5%, 50% and 95% grant shared entitlements with individual choices and late-join catch-up. Skill offers take priority and freeze gear timers; paused simulation freezes both. Typed equipment requests retain server-owned slot identity, generation checks and independent monotonic offer IDs. Keep Current Gear consumes a loot choice without changing the build; timeout still equips option zero.

All 48 original equipment illustrations share one file-backed managed 1024×768 RGBA texture (3 MiB), prewarmed at startup and reused by Run Details. It retains no decoded CPU pixmap. The phone receives the same atlas PNG once via the allowlisted /art/item-icons.png route and switches atlas coordinates only for equipment offers. Existing skill-card structure, fonts and styling are retained. Offline Java packing validates transparent sources and records the catalog-to-cell manifest; originals and generation prompts are kept separately from runtime resource loading.


Late-join catch-up snapshots skill and item entitlements once per fresh participant. Fixed, bounded class-rank and equipment sequences grant older entitlements immediately; only three inherited skill offers and two inherited gear offers remain, each with a 15-second host duration. Cached immutable foundation entries (skill ID/icon/rank and item ID/icon/slot), legacy summaries and remaining counters are published without rebuilding them per frame. The phone reuses the existing atlases and only rebuilds the compact icon rows when their foundation content changes. Gear initializes before skills so skill previews include its effective stats; fresh arrival health is filled after both foundations, while the active-participant reconnect guard preserves health and state. New normal offers wait behind inherited gear, then return to the existing 30-second skill-priority flow. Offers carry their duration to the phone so progress rails work for both clocks. No textures, pools or per-frame build layouts were added.
